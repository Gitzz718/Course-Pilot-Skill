# Course Pilot · 课程领航

**先帮你看清学习位置，再由你决定下一步。**

以「节奏感 + 反馈感」持续跟踪习题型课程的 AI Skill。默认做学习管家，按需做辅导老师：不把每次汇报变成上课，不把“看懂了”记成“独立会做”。

> **早期试用版：v0.1.0-beta.1。** 有个人使用经验作为设计来源，但最新规则尚未完成陌生用户、跨模型真实会话验证；不承诺提分或全学期效果。这是指令与模板包，不是独立软件、后台服务或自动提醒应用。

## 它解决什么问题？

- **不知道跟到哪里：** 对照老师要求、自己的进展、具体缺口，给出预算内的下一步。
- **学了但不知道是否会用：** 区分理解自述、辅助完成、独立通过、变式通过、延迟复测，不虚构掌握率。
- **断更后不敢重启：** 先确认眼前任务，从一项可开始的动作恢复，不要求补齐全部历史日报。
- **AI 太爱安排和催学：** 先协商目标、材料与保存位置；计划完成不自动开始第一课。

## 适合谁，不适合谁？

适合正在学习数学、理工类等习题型课程，希望持续跟踪进展、安排复习或临考取舍，并愿意提供必要资料与真实作答的人；也可只问一道题，不建档。

不适合把它当成自动读取教务通知、持续后台监控、考试成绩预测器的人。论文、实验、创作与开放论述类课程尚无专门适配验证；需要整门课自足教材生成时，这也不是本项目默认目标。

## 使用前需要什么？

- 一个能读取 Markdown 指令的 AI 助手；完整用法需要它能继续读取 `references/` 中的相对文件。
- 持续档案需要文件读写工具及你授予的权限；无文件工具时只能在会话内使用接续摘要。
- 手写批改需要可读图能力；扫描 PDF 可能需要宿主提供 OCR 或转换工具。本包不自带解析器。
- 不要求安装 Obsidian，不绑定特定模型或付费接口；但效果依赖模型和宿主能力，不代表已逐一兼容测试。
- 资料提交给 AI 后如何处理，受你使用的模型服务和宿主设置影响；不要上传无权分享的材料或敏感信息。

## 安装：先选一种方式

### 方式 A：宿主支持 Skill 文件夹

1. 下载本仓库：GitHub 页面 `Code → Download ZIP`，解压。
2. 把包含 `SKILL.md` 的目录作为 `course-pilot` 文件夹，完整放进宿主文档指定的技能目录，保留 `references/` 与 `CHANGELOG.md`。
3. 重开会话或按宿主说明刷新技能，确认能发现 `course-pilot`。
4. 如已有同名技能，先备份再替换；升级技能不要覆盖个人学习数据。

本包采用 `SKILL.md`（含 name/description）+ 相对参考文件的结构。不同宿主的安装路径和调用语法不同，不要把某一软件的路径当成通用标准。若宿主只接受入口文件、不支持后续读取参考文件，完整能力不可用。

### 方式 B：没有 Skill 安装入口

把本包放在 AI 获准读取的目录，告诉它：

> 请读取此目录中的 SKILL.md，按我的请求读取相关 references 文件。先按 Course Pilot 帮我了解需求和定位，不扫描整个工作区，不写文件或自动开课；如需建档，先说明准确路径与范围让我确认。

将“此目录”替换为你的真实路径。若 AI 无法读取本地文件，可把入口正文及当前任务所需参考模块发到会话中；这只是手动加载，不等于已安装或会跨会话自动记忆。

## 第一条消息怎么说？

**持续管理：**

> 用 course-pilot 帮我管理《自动控制原理》。我希望知道自己跟到哪、还缺什么，不要一开始就上课。我自报学到第三章，本周大约能投入两小时。先问必要信息、给定位和最小方案，确认保存位置后再建档。

**只更新，不教学：**

> 今天完成了第三章作业，但有两题看了解答才做出来。只更新和分析进度，暂时不出题。

**只答一道题：**

> 只帮我解释这道题，不建档，不做整门课规划。

**断更重启：**

> 我有一段时间没汇报了。先核对记录时效和眼前任务，给我一个最小重启动作，不要求补齐历史。

更多见 [合成使用示例](examples/first-use.md)。示例不是实际用户成效或模型运行记录。

## 正常使用会发生什么？

临时问题直接处理；首次持续管理时，AI 应先了解需求，核对候选资料是否属于本课，再复述定位和未知项，提出最小记录方案。你确认准确路径与范围后才保存，结束后交还下一步选择权。

持续管理时维护两个相互驱动的视图：

- **节奏：要求 → 现状 → 差距 → 行动。** 分清教学跟进、任务提交、能力验证缺口。
- **反馈：尝试 → 证据 → 变化 → 再检验。** 没有作答证据就不声称能力提升。

规划可建议 P 预习、F 跟课、C 查缺、S 冲刺四种模式。它们是安排方式，不是强制流程；时间不足时明确暂缓项，不靠加任务伪装完成。

## 会创建什么？

技能安装目录只放方法论。你确认保存后，个人数据另放指定目录，例如 `course-pilot-data/`：

- 每科的 `course-state.md`：当前情况、节奏与反馈视图，按需扩充证据、资源、行动。
- `_总览.md`：有跨科安排需要时才建。
- `_规则覆盖.md`：只记录你明确拍板的个人规则。
- `SCENARIOS.md`：你同意留存复盘场景时才建；**记录许可不等于公开许可**。

这些不是需要全部填完的入门问卷。没有文件权限时，不应声称已经保存。换会话需要宿主仍可访问档案，或由你重新提供摘要；不承诺自动记忆。

## 架构

- `SKILL.md`：入口路由、双视图、权限与真实性原则。
- `references/planning.md`：初始化协商、四模式、预算、断更与通知边界。
- `references/tutoring.md`：按风险批改、材料核验与证据规则。
- `references/records.md`：数据口径、模板与纯聊天接续。

参考模块按需读取，不要求每次加载全部课程或历史。公开维护用例见 [维护与回归检查](CONTRIBUTING.md) 和 [验收场景](tests/SCENARIOS.md)，不依赖作者私人数据。

## 已知限制与验证状态

- 规则不等于强制执行器。模型仍可能误读、算错、忽略授权边界；重要安排与答案需要核对。
- 同一模型出题和判题不构成独立认证；单题通过不代表全章稳定掌握。
- 通知依赖实际可用且设置成功的外部工具；否则只是待办或会话内提示，**没有后台推送**。
- 最新初始化和公开包装只完成静态检查与规则场景审阅，没有完成真实用户端到端教学验证或成绩因果评估。
- 建档与阅读会占时间；若维护比学习还重，请缩小记录范围。

## 反馈

仓库公开后，可通过 GitHub Issues 反馈：你的目标、宿主/模型、最小复现、预期与实际行为、脱敏片段。不要贴原始个人档案、学号、成绩截图、令牌或受限课件。首次使用是否顺利，比“功能越多越好”更有参考价值。
